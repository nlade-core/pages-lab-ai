What can't be compared directly

  • Different runtimes and builds. Ollama runs a 4-bit GGUF (Q4_K_M) on llama.cpp/Metal. Chrome and Edge run their own builds of their models, with their own compression and their own GPU path. Even Phi-4-mini, the same weights in Edge and Ollama, is not the same binary.
  • Gemini Nano has no public weights. The gemma3n/gemma4 rows are open relatives, not Nano.
  • Settings. Ollama runs at temperature 0, top_k 1, seed 42. The Prompt API may reject or quietly ignore temperature/topK on ordinary web pages. Each browser row records what create() accepted and what the session reported.
  • Tokens. Ollama reports the tokens it generated, timed by the server. The Prompt API reports no output tokens. The browser figure comes from running measureInputUsage() on the reply text, divided by wall-clock time after the first token. Chars/s is the fairer comparison across runtimes.
  • Time to first token. Both numbers are wall clock from sending the prompt, after a warm-up. Ollama's includes a localhost HTTP round trip. The browser's excludes session creation, which is recorded separately as create_ms.
  • Throughput uses the open-ended items only. A one-word answer arrives in one or two chunks, so its chars/s is noise.
  • n = 1. One run per item. A single pass or fail is anecdote, not a ranking.
