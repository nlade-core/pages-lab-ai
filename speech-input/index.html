Speech Input — On-Device Only

Say something. Transcribed entirely on this machine, or not transcribed at all — this page refuses to fall back to a cloud recognizer, ever.

Uses Chrome's on-device Web Speech API (shipped Chrome 139, August 2025), backed by Google's local SODA model — not related to the Whisper page, and not the classic SpeechRecognition most sites use, which sends audio to Google's servers by default. Part of pages-lab-ai — source.

How this stays local

  • Every request this page makes sets processLocally = true. Per spec, that's not a preference — the browser must process locally or fail; it does not silently fall back to a cloud recognizer.
  • If the on-device language pack isn't installed, start() fails outright with a language-not-supported error. This page treats that as "unavailable, stop here" — there is no code path anywhere in this file that retries without processLocally, which is the one mistake that would quietly reopen the cloud path.
  • This entire page makes zero fetch/XMLHttpRequest/WebSocket calls — view-source and check. Nothing the page's own code does can send your voice or transcript anywhere, local or remote.
Don't just trust this text — verify it yourself: once the status below says "available" and you've used Start once successfully, turn off Wi-Fi entirely and try Start again. If it still transcribes with no network at all, it's genuinely local. That real test is the only actual proof; a web page can't demonstrate the absence of network activity to itself.
